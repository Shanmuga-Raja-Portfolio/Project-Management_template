# Level 1: Starter

A short interview, then a small project folder with only the files your answers justify. Nothing is installed.

> Please read the [disclaimer](../../README.md#disclaimer) before installing any tool.

## Who it is for

- You work with an AI agent that reads and writes files in a project folder: Claude Code, Cursor, GitHub Copilot, Codex, OpenCode, Aider, Gemini CLI and similar. The folder can hold code, research or writing.
- You work alone, or you are the single owner who runs the agent.
- You are not sure what you need yet. Level 1 is the safe default, and you can add tools later when a named trigger fires.
- Existing projects are welcome. Files are added alongside your work; nothing is moved, and existing files are never overwritten.

**Chat window only?** See [guides/chat-window.md](../../guides/chat-window.md).

Not yet supported (planned for v0.2): several people editing the same status and log files on parallel branches.

## Short path (5-15 minutes)

1. Start the interview (see [How to run](#how-to-run)). With Claude Code, the skill is quickest.
2. Answer up to eight questions (Q01 to Q08). Ones your earlier answers already cover are skipped.
3. Read the proposed `SETUP_DECISIONS.md` and file list. Approve, or ask for changes.
4. The LLM then drafts `PROJECT.md` with you in two or three prompts (goal, scope, done when).
5. Continue with [Your first working session](#your-first-working-session).

## What you get

`SETUP_DECISIONS.md` records what was chosen, why, what was declined, and the trigger that would change each decision. With nothing beyond the minimal set, it is 5 to 10 lines.

You also get a starter folder from [`template/`](../../template/README.md), cut down to what your answers need:

| File | Purpose | Kept when |
|---|---|---|
| `AGENTS.md` | The one instruction file. Says to read `RULES.md` first, then what to read for which task. | Always, unless chat window only |
| `RULES.md` | Short working rules: General, Documentation, Agent, Code. Yours to edit. The interview may drop whole sections (Code for non-code projects; a chat-window set keeps General and Documentation) but never rewrites them. Code rules apply to new code; an existing project's style wins. | Always |
| `PROJECT.md` | Goal, users, scope, out of scope, done criteria, constraints, risks. | Always |
| `STATUS.md` | Now, next, blocked. Overwritten each session. | Always |
| `SETUP_DECISIONS.md` | The record of this setup. | Always |
| `DECISIONS.md` | Append-only decision log (D-001, D-002, ...). | You chose a decision log (Q07) |
| `LOG.md` | Append-only work log with action types. | You want one. Optional for code in git, where `git log` already records actions |
| `knowledge/` | Notes others will rely on, in OKF v0.2 format. | You chose a knowledge folder (Q07) |
| `stages/` | Numbered stage folders. | Only for a process that repeats |
| `.pmkit/` | `pmkit.py` (check, prune, sync, log, decide) and `adapters.txt`. Python 3.8+, no extra packages. | An agent works in the folder |
| `CLAUDE.md` or another adapter | Only for an agent that does not read `AGENTS.md` itself. For Claude Code: one header line plus `@AGENTS.md`. Generated by `pmkit.py sync`. | Your agent needs it (Q06) |
| `.gitignore` | Keeps local venvs and `.env` files out of git. Never overwrites yours. | The folder is in git |
| `README.md` (template) | Explains each file. | Read once, then delete |

- Many agents read `AGENTS.md` directly and need no adapter (checked 2026-10-17; verify for your version).
- Your upkeep answer (Q07) caps the total number of files and tools. The rules are in [interview/MAPPING.md](../../interview/MAPPING.md).
- Not included: installed tools, a dashboard, a persona, or a fixed set of files every session must read.

## Your first working session

1. Read `PROJECT.md` and fix anything the draft got wrong. `python .pmkit/pmkit.py check` lists any `<fill in` placeholders left.
2. Start each session with: "Read AGENTS.md and STATUS.md." `AGENTS.md` sends the agent to `RULES.md` first. In a chat window that cannot read files, paste `STATUS.md` (and `PROJECT.md` and `RULES.md` if the chat has no copy) instead.
3. End each session by asking the agent to overwrite `STATUS.md` (now, next, blocked). If you kept `LOG.md`, ask it to append an entry too.
4. If something keeps going wrong, see [guides/adding-tools-mid-project.md](../../guides/adding-tools-mid-project.md). You do not need to redo the setup.

### Keeping the folder tidy

If `.pmkit/` is in your folder:

| Command | When |
|---|---|
| `python .pmkit/pmkit.py check` | Now and then. Warns about broken links, missing files, leftover placeholders and out-of-date adapters. Details: [What check does](../../guides/what-this-is-not.md#what-check-does). |
| `python .pmkit/pmkit.py prune` | After you delete a file, to remove the lines that pointed to it. Try `--dry-run` first. |
| `python .pmkit/pmkit.py sync` | After editing `AGENTS.md`, only if `.pmkit/adapters.txt` enables an adapter. If a generated file was edited, sync refuses and shows the difference; move the edit into `AGENTS.md`, then run `sync --force`. |
| `python .pmkit/pmkit.py log --type UPDATE --summary "..."` | To log work, if you kept `LOG.md`. |
| `python .pmkit/pmkit.py decide --title "..." --why "..." --revisit "..."` | To record a decision, if you kept `DECISIONS.md`. |

## How the interview works

- The questions are the ones tagged `L1` in [interview/QUESTIONS.md](../../interview/QUESTIONS.md): Q01 what is being produced, Q02 one-off, repeatable or ongoing, Q03 duration and size, Q04 new or existing material, Q05 solo, team or handoff, Q06 which agent or editor, Q07 how much upkeep you will keep up, Q08 (short form) whether the work includes personal or confidential data and may go to a cloud AI service.
- [interview/CONDUCT.md](../../interview/CONDUCT.md): one question at a time, plain language, implied answers skipped, a proposal before anything is created. It never asks for secrets or API keys.
- Before proposing files, the LLM looks for conventions you already have (`docs/adr`, `CONTRIBUTING`, an existing `AGENTS.md`, `CLAUDE.md` or `.cursor/rules`, review bots in CI) and reuses them.
- [interview/MAPPING.md](../../interview/MAPPING.md) turns answers into files. "Recommend nothing extra" is a valid outcome.
- [interview/OUTPUTS.md](../../interview/OUTPUTS.md) shows the `SETUP_DECISIONS.md` layout, including the short form.

## How to run

All three options use the same questions and output format.

### A. Claude Code skill

```bash
bash scripts/install-skill.sh            # macOS / Linux / Git Bash
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-skill.ps1   # Windows PowerShell
```

`-ExecutionPolicy Bypass` applies to that one command only; it does not change your system setting. The same goes for `new-project.ps1` below.

Then open your project in Claude Code, type `/project-setup`, and choose Level 1.

### B. Any LLM (ChatGPT, Gemini, a local model, ...)

Paste [RUNFILE.md](RUNFILE.md) into a new chat, or attach it. It is self-contained and roughly 7k tokens.

- On a local model, raise the context size first. Ollama's default is small, so set `num_ctx` to at least 16k ([guides/local-models.md](../../guides/local-models.md)).
- In agent mode the model creates the files directly. Otherwise it prints each file in a box for you to save.
- No git? Open the file on GitHub and use "Raw", "Copy raw file" or "Download raw file".
- `RUNFILE.md` is generated by `scripts/build_runfiles.py`. Please do not edit it by hand.

### C. By hand

1. Answer the `L1` questions in [interview/QUESTIONS.md](../../interview/QUESTIONS.md).
2. Copy only the files you need:

   ```bash
   bash scripts/new-project.sh --minimal /path/to/your-project
   bash scripts/new-project.sh --only AGENTS.md,RULES.md,PROJECT.md,STATUS.md,SETUP_DECISIONS.md /path/to/your-project
   ```

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\new-project.ps1 -Minimal C:\path\to\your-project
   ```

   `--minimal` copies `AGENTS.md`, `RULES.md`, `PROJECT.md`, `STATUS.md`, `SETUP_DECISIONS.md`, `.gitignore` and `.pmkit/`. With no option it copies the full set. Existing files, including your `.gitignore`, are never overwritten. When `.pmkit/` is copied, the script shows `prune --dry-run` and asks before pruning (`--yes` skips the question), and runs `sync` only if an adapter is enabled. Without Python 3, it prints the commands for you to run.
3. Delete anything else your answers do not justify, then run `python .pmkit/pmkit.py prune`.
4. Fill in `SETUP_DECISIONS.md` in the format from [interview/OUTPUTS.md](../../interview/OUTPUTS.md).

## Which model

Any capable LLM works. Level 1 needs no local model and no API key beyond what your chat or agent already uses. If your Q08 answer says content must not go to a cloud service, use a local model or an approved enterprise service. Nothing routes work to the cloud by default.
